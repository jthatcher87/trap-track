PNiXStudio · CLIENT SETUP

Connect your private journal

You can use Trap Track locally without Google. To sync across devices, create your own Google Apps Script (GAS) project and private Sheet. Allow about 20–30 minutes; a desktop browser makes copying files easier.

Back to Settings

1. Before you begin

Sign into the Google account that should own your journal. Each person needs a separate project, Sheet, token, and passphrase. You do not need your own GitHub repository to use the hosted app.

Keep a password manager ready. Your Google password, the connection access token, and your journal passphrase are three different things. Never send any of them to support.

2. Create the Apps Script project

  1. Open Google Apps Script. Confirm the correct Google account using the profile picture.
  2. Choose New project. Rename “Untitled project” to Trap Track — My private journal.
  3. In the Editor, open Code.gs. Select all its default code and replace it with the complete Code.gs contents below. Copy only the code inside the panel.
  4. Next to Files, click + → HTML. Enter Bridge as the name (Google adds .html). Replace all its contents with Bridge.html below.
  5. Open Project Settings (gear). Enable Show “appsscript.json” manifest file in editor. Return to Editor, open appsscript.json, and replace its complete contents with the manifest below.
  6. Save the project with the save icon or Ctrl+S / Cmd+S. All three files must be present.

No Sheet needs to be created manually. The setup function creates and formats it in the next step.

function setup() {
  const p = PropertiesService.getScriptProperties();
  if (!p.getProperty('SHEET_ID')) {
    const ss = SpreadsheetApp.create('Trap Track · Private encrypted journal');
    const sheet = ss.getSheets()[0]; sheet.setName('Vault');
    sheet.getRange('A1:D1').setValues([['Revision','Updated UTC','Encrypted chunk','Format']]);
    sheet.getRange('A1:D1').setBackground('#183439').setFontColor('#ffffff').setFontWeight('bold');
    sheet.setFrozenRows(1); sheet.setColumnWidth(1,120);sheet.setColumnWidth(2,210);sheet.setColumnWidth(3,600);
    p.setProperty('SHEET_ID', ss.getId());
  }

  // https://jthatcher87.github.io (origin only, no repository path).

function doGet(e) {
  const p=PropertiesService.getScriptProperties();
  const origin=p.getProperty('ALLOWED_ORIGIN')||'';
  if (!/^https:\/\/[a-zA-Z0-9.-]+(?::[0-9]+)?$/.test(origin)) return HtmlService.createHtmlOutput('Set a valid HTTPS ALLOWED_ORIGIN in Script Properties.');
  const t=HtmlService.createTemplateFromFile('Bridge');
  t.origin=origin;t.nonce=String(e.parameter.nonce||'').replace(/[^a-zA-Z0-9-]/g,'');
  return t.evaluate().setTitle('Trap Track private connection').setXFrameOptionsMode(HtmlService.XFrameOptionsMode.ALLOWALL);
}
function journalApi(request) {
  const p=PropertiesService.getScriptProperties(), expected=p.getProperty('ACCESS_TOKEN');
  if (!expected || !request || typeof request.token!=='string' || !equal_(expected,request.token)) throw new Error('Connection not authorized. Check your private access token.');
  const lock=LockService.getScriptLock();lock.waitLock(10000);
  try {
    const ss=SpreadsheetApp.openById(p.getProperty('SHEET_ID')),sheet=ss.getSheetByName('Vault');
    const rows=sheet.getLastRow(), revision=rows>1?String(sheet.getRange(2,1).getValue()):'0';
    if(request.action==='read') {
      const text=rows>1?sheet.getRange(2,3,rows-1,1).getValues().map(r=>{if(typeof r[0]!=='string'||r[0].slice(0,3)!=='v1:')throw new Error('Invalid journal chunk.');return r[0].slice(3);}).join(''):'';
      return {revision:revision,envelope:text?JSON.parse(text):null};
    }
    if(request.action!=='write')throw new Error('Unknown journal action.');
    const payload=request.payload||{};
    if(String(payload.revision)!==revision)return {ok:false,conflict:true};
    const v=payload.envelope;
    if(!v || v.v!==1 || !/^[A-Za-z0-9+/=]+$/.test(v.data||'') || !/^[A-Za-z0-9+/=]{24}$/.test(v.salt||'') || !/^[A-Za-z0-9+/=]{16}$/.test(v.iv||''))throw new Error('Invalid encrypted journal.');
    const text=JSON.stringify(v);if(text.length>1500000)throw new Error('Journal exceeds 1.5 MB. Export a backup and archive older entries.');
    const next=Utilities.getUuid(),now=new Date().toISOString(),out=[];
    for(let i=0;i<text.length;i+=40000)out.push([next,now,'v1:'+text.slice(i,i+40000),'AES-GCM / PBKDF2-SHA256 v1']);
    // Prefix every chunk so no chunk can be interpreted as a spreadsheet formula.
    if(sheet.getMaxRows()<out.length+1)sheet.insertRowsAfter(sheet.getMaxRows(),out.length+1-sheet.getMaxRows());
    sheet.getRange(2,1,out.length,4).setNumberFormat('@').setValues(out);
    if(rows>out.length+1)sheet.getRange(out.length+2,1,rows-out.length-1,4).clearContent();
    SpreadsheetApp.flush();return {ok:true,revision:next};
  } finally {lock.releaseLock();}
}

3. Run setup and authorize Google

  1. In Editor, select setup in the function dropdown next to Run. Click Run. Do not run doGet or journalApi directly.
  2. When asked, click Review permissions, then choose the same Google account.
  3. Read the permission request. The script requests access to your spreadsheets; this is broader than a single Sheet. The supplied code uses the journal Sheet ID it creates.
  4. A personal script may show “Google hasn’t verified this app.” Continue only for the project you just created with the supplied code, after reviewing it and the requested access. If offered, use Advanced → Go to [your project name] (unsafe), then grant the requested spreadsheet access. If Google or your organization blocks it, do not bypass the policy; use local journaling and ask your administrator.
  5. Complete any Google phone/security checks directly with Google. Wait for Execution completed in the execution log. If authorization interrupts the run, select setup and Run again.

Successful setup creates Trap Track · Private encrypted journal with a Vault tab, plus SHEET_ID and ACCESS_TOKEN in Script Properties. Running the supplied setup again reuses the existing Sheet and token.

4. Check the Sheet and connection properties

  1. Open Project Settings → Script Properties. Refresh if necessary. Copy ACCESS_TOKEN into your password manager; keep its entire value.
  2. Add a property named ALLOWED_ORIGIN. For the hosted Trap Track app, enter exactly https://jthatcher87.github.io. Save properties. Do not include /trap-track/, a trailing slash, spaces, or quotes.
  3. Find the new Sheet in Google Drive, or open https://docs.google.com/spreadsheets/d/YOUR_SHEET_ID/edit using your own SHEET_ID value.
  4. Check Share → General access is Restricted. Do not publish the Sheet to the web or share it with other clients.
PropertyWhat to use
SHEET_IDGenerated by setup; leave unchanged.
ACCESS_TOKENGenerated by setup; private connection credential.
ALLOWED_ORIGINHTTPS app origin only. For your own hosting, use its actual origin.

The Vault header row should read Revision, Updated UTC, Encrypted chunk, Format. Before the first sync there are no journal rows. Do not rename Vault, edit its cells, sort its rows, or insert formulas. It stores an encrypted snapshot, not one readable row per reflection.

GitHub Pages repository paths share an origin. For a separately hosted app, use that hosting origin; a dedicated custom domain gives a tighter origin boundary.

5. Deploy your web app

  1. In Apps Script, choose Deploy → New deployment.
  2. Next to Select type, open the gear menu and choose Web app.
  3. Enter a description such as “Trap Track journal connection v1”. Set Execute as: Me (the journal owner).
  4. Set Who has access: Anyone. “Anyone with Google account” is not equivalent: the app’s background connection needs access without an interactive Google sign-in.
  5. Choose Deploy and complete any authorization Google requests.
  6. Copy the Web app URL ending in /exec into your password manager. Do not use the deployment ID, editor URL, Sheet URL, or a /dev test URL.

“Anyone” makes the connection bridge reachable; it does not make the Sheet public. Journal reads and writes still require your access token, and journal content is encrypted in the app. Anyone who obtains the token can download or replace encrypted data, even without its passphrase. If Anyone is unavailable under your account policy, this connection cannot be used as configured; continue locally.

6. Connect Trap Track

  1. Open Trap Track → Settings.
  2. Paste your /exec Web app URL into Apps Script web app URL.
  3. Paste your ACCESS_TOKEN into Private access token, then choose Save settings & connect.
  4. Wait for “Connected. Unlock your journal, then sync from My journal.” Connection checks access; it does not upload your reflections by itself.
  5. Open My journal and enter a unique passphrase of at least 12 characters. On an existing journal, use its existing passphrase. Store a recovery copy yourself: the app cannot reset it or recover encrypted content.

Your token and passphrase stay in memory for the session. Reconnect after locking or closing the app. The endpoint and appearance preferences remain on this device.

7. Verify with a harmless test

  1. Create a reflection titled “Connection test” with no personal information. Continue through the steps and choose Save reflection.
  2. In My journal, choose Sync with my Sheet. Wait for “Encrypted journal synced with your Google Sheet.” A local-save message alone does not confirm cloud sync.
  3. Open your Sheet. Vault should now show a revision, UTC timestamp, encrypted chunk(s) beginning with v1:, and format. Unreadable content is expected.
  4. For a full read-back check, open the app in a second browser profile or device with no existing local journal. Connect using the same endpoint and token, unlock using the same passphrase, and sync. Confirm “Connection test” appears. Never clear your only local copy to run this check.
  5. Delete “Connection test” inside the app, sync, then sync any second device. The test should disappear. Do not clear Vault cells manually; Google history and backups may retain older snapshots.

Setup is complete when connection succeeds, a sync is acknowledged, and a clean second device can read the test. Until then, keep an encrypted backup of any real entries.

8. Everyday use and another device

Save reflections to this device, then sync whenever you want the Sheet updated. Sync needs Internet and is manual. On another device, open the same app, connect with the same endpoint/token, use the same passphrase, then sync. Sync before and after editing when moving between devices; keep device clocks accurate.

Use My journal → Encrypted backup regularly. Restore backup requires its passphrase. Lock the journal on shared devices. Clearing browser data can remove local records; unsaved drafts are lost when closing or locking. The Sheet is storage, not a readable clinician dashboard or emergency monitoring service.

Troubleshooting

What you seeWhat to check
setup is missing / syntax errorSave Code.gs, copy the entire file without Markdown fences, and check that Bridge is an HTML file.
No Sheet or propertiesRun setup under the correct account, complete authorization, and check the execution log. Refresh Script Properties.
Connection timed outCheck Internet, exact ALLOWED_ORIGIN, /exec URL, Anyone access, and that the deployed version includes all three files. Browser privacy extensions may block the embedded bridge; try a supported browser/profile without changing account security settings.
Connection not authorizedCopy the full ACCESS_TOKEN from the matching project. Remove accidental spaces. Reconnect after a token change.
No HTML file named BridgeCreate an HTML file named Bridge, paste Bridge.html, save, and deploy a new version.
Different passphrase or damaged dataUse the original journal passphrase. Do not delete data, replace SHEET_ID, or create a new passphrase over the existing journal. Preserve backups.

Permission denied / Sheet missingConfirm Execute as Me, the owner account, SHEET_ID, the Sheet is not trashed, and Vault exists. Reauthorize if you revoked access.
Quota or size limitKeep an encrypted backup. Retry quota failures later. The backend accepts snapshots up to 1.5 MB; do not edit encrypted chunks to shrink them.

Updates, token changes, and stopping sync

Update code: export an encrypted backup first. Replace the relevant project files without deleting Script Properties. Choose Deploy → Manage deployments → select the existing web app → Edit (pencil) → Version: New version → Deploy. Keeping the deployment preserves its URL. Merely saving code does not update a versioned deployment.

Exposed token: replace ACCESS_TOKEN in Script Properties with a new long, randomly generated secret (at least 32 characters; use a password manager generator). Save and reconnect each device with the new token. Do not change the passphrase or SHEET_ID. Property changes apply without a new code deployment.

Stop cloud access: Disconnect Sheet in app Settings clears the local connection; it does not revoke the remote endpoint. To disable that endpoint, archive the deployment through Deploy → Manage deployments. Export a backup before removing the Sheet or script. Deleting a reflection and syncing is a logical deletion; history and backups can retain older copies.

Getting help: share the exact error text and which numbered step failed. Redact tokens, passphrases, Sheet IDs, deployment URLs, account information, and journal text from screenshots.
